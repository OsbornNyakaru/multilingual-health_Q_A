# program.md: the experiment loop

The loop an agent (or a human) runs to improve the score, modelled on karpathy/autoresearch:
a frozen harness, one editable file, one change per experiment, a measured verdict, and a
ledger. The difference from autoresearch is where things run: code is edited on the Mac, GPU
work runs on molab, and results travel back through a private Hugging Face dataset.

## The pieces

| file | role | who edits it |
|---|---|---|
| `autoresearch_nlp/prepare.py` | frozen harness: split, metric, submission schema. Hash-pinned in the runner | nobody |
| `autoresearch_nlp/experiment.py` | **the one editable file**: retrieval, prompts, generation, routing | the loop |
| `notebooks/molab_runner.py` | frozen runner on molab: runs queued specs at their git SHA | rarely (re-open on molab after a change) |
| `scripts/exp.py` | local CLI: `new`, `submit`, `pull`, `status`, `submission` | rarely |
| `experiments/specs/EXP-NNN.json` | one spec per experiment | `exp.py new` |
| `experiments/RESULTS.md` | the human ledger (feed this to the note-taker) | generated by `exp.py pull` |
| `experiments/BEST.json`, `results.jsonl` | per-subset best and every scored run | generated |
| `vault/experiments/EXP-NNN-*.md` | one vault note per run, linked from `vault/00_INDEX.md` | generated |

Private HF datasets: `nyakaruosborn/afro-health-qa-data` (competition CSVs) and
`nyakaruosborn/afro-health-qa-runs` (`queue/` specs, `runs/<run_id>/` predictions + `result.json`).
Predictions contain competition text, so they never go to GitHub (`experiments/runs/` is gitignored).

## How a run is judged

- Every run is scored on **two sets**: `held_out` (2,088 rows of Train, pool = the rest of Train)
  and `val` (the host's Val, pool = all of Train). Val has no exact duplicate questions, like Test,
  so it is the better proxy; held-out keeps us honest across time.
- Scores are `0.37·rouge-1 + 0.37·rouge-l` with the whitespace tokenizer (max 0.74, judge not
  measured). The summary number is **test-mix**: the per-subset scores averaged with each subset's
  share of Test.csv as the weight (Eng_Uga 28%, Aka_Gha 19%, Eng_Gha 19%, Lug_Uga 14%, ...).
- **Adoption is per subset.** A run becomes the best for a subset when it beats that subset's
  current best by **≥ +0.003 on both sets**. Only full-set runs (`held_out=0, val=0`) are eligible;
  smaller runs are screens. The composite (best run per subset) is the current best overall.
- Noise: about ±0.005 on the full held-out. Differences under 0.003 are not real.

## One iteration

1. **Pick the next lever** from the queue below (or a hypothesis note). One change only.
2. **Edit `experiment.py`** if the lever needs new code. Run `make test`. Commit and push.
3. **Draft the spec**: `python scripts/exp.py new --from best --set key=value --hyp H-0xx --desc "..."`
   (`--from` takes `best`, a run_id or an EXP id; `--subsets Aka_Gha,Eng_Gha` limits the rows;
   `--eval held_out=500` makes a quick screen; it refuses more than one changed key unless
   `--allow-multi`).
4. **Queue it**: `python scripts/exp.py submit` (refuses if the code isn't pushed: molab fetches by SHA).
5. **Run it**: on molab, the runner is open with **keep watching** on, or press **Run queue**.
6. **Record it**: `python scripts/exp.py pull --wait`. This scores, decides per subset, regenerates
   `experiments/RESULTS.md`, and writes the vault note. Commit `experiments/` and `vault/`.
7. **Decide what's next.** A code change that won nowhere: `git revert` it (main is public, never
   reset). Three non-wins in a row on the same idea: change the mechanism, not the parameter.
   Simplicity wins ties: removing code for an equal score is a win.

Crashes come back as `status: crash` with the traceback in the vault note. Fix and submit a new
spec (each spec gets a new run_id, so nothing resumes stale answers by accident).

## Submitting to Zindi

Every best run needs test predictions: `exp.py new --from <run_id> --eval test=0 --desc "..."` (same config, test set only),
then submit and pull. `python scripts/exp.py submission` assembles the per-subset composite into
`experiments/runs/submissions/composite_*.csv` (gitignored). Record the public score in the ledger.
The first submission also settles H-013 (does the grader tokenize like us).

## Queue (from the 2026-10-01 strategy review; evidence in vault/experiments and the review)

Retrieval first: on Eng_Uga, Lug_Uga, Swa_Ken and Eng_Ken (~58% of Test) ~90% of Val answers
already exist verbatim in Train, so choosing the right existing answer beats writing a new one.
Generation only matters for Aka_Gha, Eng_Gha and Amh_Eth.

1. `select=vote` (answer voting over top-50 neighbours) [CPU]
2. `embedder=BAAI/bge-m3` (dense)
3. `embedder=intfloat/multilingual-e5-large` + `query_prefix="query: "`, `passage_prefix="passage: "`
4. hybrid lexical + dense retrieval (needs code)
5. cross-encoder rerank of the top-20 (`BAAI/bge-reranker-v2-m3`) (needs code)
6. fine-tuned bi-encoder, question → answer (needs code)
7. `mode=rag_few_shot` on `--subsets Aka_Gha,Eng_Gha,Amh_Eth` with Qwen2.5-7B, then a model screen
   there (AfriqueLlama-8B, Gemma-2-27B, Qwen2.5-32B, Sunflower-32B once access is granted)
8. vLLM generation (needs code) before any large generation sweep
9. RAG-enriched LoRA fine-tune (reference: r64, α64, dropout 0.5, 3 epochs, lr 2e-4, k=3 excluding self)
10. judge stand-in on the final candidates; decoding (beams) last

Dropped: zero-shot / fixed-example few-shot screens over all subsets, Aya (licence), Llama
(no access).
